Exact publication rendering environment
=======================================

Purpose and scope
-----------------

The publication figure builders are deterministic only when their raster and
font-rendering stack is also fixed.  This file specifies the environment used
to rebuild the seven checked-in PNGs and the BHS PDF in this release.

These are rendering requirements.  They are separate from the fitting, CASA
and MIR requirements in requirements.txt, constraints-fitting.txt,
requirements-casa-linux-cp312.txt and requirements-mir.txt.  Do not replace
the fitting environment with this minimal renderer.

Portable invocation
-------------------

The host requires bubblewrap (`bwrap`).  Supply an independently prepared
read-only Ubuntu rootfs and a new output directory that does not yet exist:

  python3 scripts/render_publication.py \
    --rootfs /path/to/ubuntu2404-render-rootfs \
    --release . \
    --output /path/to/new-render-output

The script mounts the release read-only, gives only the output directory write
access, creates fresh XDG cache/config directories, checks the runtime versions
above, runs the unchanged BHS and SED builders, requires seven PNGs and one
PDF, and verifies that the scientific input hashes did not change.

Reconstructing the tested rootfs
--------------------------------

The tested rootfs was constructed from Canonical's official archive:

  https://cdimage.ubuntu.com/ubuntu-base/releases/24.04.3/release/
  ubuntu-base-24.04.3-base-amd64.tar.gz

Archive SHA-256:

  6bc2cde3930ad088b3bb46fa45279e96d25bc3810f209850ecbe4722711874f9

After unpacking the base archive into a new rootfs, the apt source was pinned
in deb822 form to:

  Types: deb
  URIs: https://snapshot.ubuntu.com/ubuntu/20260826T000000Z/
  Suites: noble noble-updates
  Components: main universe
  Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg
  Check-Valid-Until: no

and a second stanza with the same URI, components, key and validity setting,
but `Suites: noble-security`.  Installing the versioned packages listed above
from that snapshot produced the tested runtime.  This reconstruction recipe is
recorded from the successful historical setup; it was not independently
reexecuted during the final candidate check.  The already constructed rootfs
was independently exercised again with fresh caches, and all publication
artifact tests passed.

What was verified
-----------------

- The candidate BHS PDF and PNG are byte-identical to fresh output from the
  candidate builder in this locked environment.
- Repeated fresh builds are byte-identical.
- All six SED PNGs are byte-identical to the accepted-paper copies.
- The candidate BHS PNG has the accepted dimensions and scientific layout but
  is not pixel-identical to the separately saved accepted-paper PNG: 80 pixels
  (88 channel values) differ.  This known presentation-copy difference is not
  described as an exact accepted-image match.
- The intended candidate BHS figure omits plotted error bars while retaining
  the audited uncertainty values in the data loader.

The locked final presentation suite ran 86 tests: 83 passed and three were
skipped, with zero failures or errors.  The skips occurred only because the
self-contained release intentionally does not include the adjacent manuscript
revision package.
